# M11-F 终局仪表盘视觉设计与 UE 落地

## 1. 目标与边界

M11-F 聚焦底部中央控制台的 Yaw、Pitch、Power 三只仪表。目标是在不改变 M11-C 输入、F4 引导、命中盒和发布语义的前提下，把原本只有圆底、文字和指针的旋钮升级成与 M11 控制台一致的机械航电仪表。

本轮仅修改 M11 专属 C++ Canvas HUD 与设计文档；不修改共享 Theme、地图、UMG、输入契约或求解器。按钮继续使用 M11-E 的 Image2 图标资产。

## 2. 视觉结构

每只仪表由外向内使用同一组层次：

1. 深海军蓝外圈和细亮边构成金属表壳；
2. 内凹深色表盘把仪表与控制台底板分离；
3. 270° 分段量程弧显示当前归一化位置，已完成区使用青色，剩余区使用低亮深蓝；
4. 十一枚刻度建立可读量程，其中起点、中点、终点为较长主刻度；
5. 琥珀指针表示当前输入，深色影针提升亮背景上的轮廓，中心轴使用暗色轮毂和琥珀芯；
6. F4 引导有效时，独立绿色目标缺口标记建议值，避免把“建议”误画成“当前”；
7. 仪表名称位于表壳上方，当前数值和目标数值位于表壳下方，不与指针共用旋转面。

Yaw、Pitch、Power 继续共享同一绘制原语，只替换标签、数值格式、当前归一化值和引导目标值。因此三只仪表的轮廓、刻度密度和状态语义保持一致。

## 3. 交互与数据合同

- `DrawKnob` 新增只读 `GuidanceTargetAlpha` 参数，用于绘制 F4 目标缺口；不回写交互系统。
- 指针和进度弧都使用既有 `NormalizedValue`，角度范围固定为 `-135°…+135°`。
- 点击、拖动、滚轮和键盘精度档仍使用既有中心点、半径与命中盒；视觉外扩不改变可交互区域。
- F4 引导无效时不绘制目标缺口或目标值；无效数据继续 fail closed。
- Theme v1 语义不变：当前进度为 `AccentSecondary`，当前指针为 `AccentPrimary`，目标缺口为 `Success`，文字使用 `TextPrimary/TextMuted`。

## 4. 离屏迭代结论

- v001：层叠表壳、量程弧、刻度和指针已经成立，但 Pitch 指针会穿过表盘内的名称与读数。
- v002：为表盘内文字增加深色遮罩，交叠消失，但矩形遮罩破坏了圆形仪表的整体性。
- v003：移除遮罩，把名称移到表壳上方、当前值和目标值移到下方。指针旋转面保持纯净，同时三个仪表仍能被快速对应到各自读数。

最终视觉证据：`Saved/M11F/HudCapture_v003/M11F_Hud_1280x720_v003.png`。对应 Camera Capture Contract v18 Manifest 为 `Complete/Aiming/UNCERTIFIED`，仅用于 HUD 像素与构图诊断，不替代正式可见 PIE。

## 5. 性能与后续验收

每只仪表使用固定数量 Canvas 图元：两层圆面、两层轮廓、36 段量程弧、11 枚刻度、指针和轮毂。三只固定仪表总量约 150 个简单图元，不创建纹理、材质、采样器、Tick 对象或动态资产，也不随分辨率提高细分数。

当前 UE 5.8 Development Editor 构建成功；fresh NullRHI `ABTS.M11C.HUD.Unit` 9/9、`ABTS.M11D.HUD.Unit` 2/2，分别记录在 `Saved/Logs/M11F_HUD_M11C.log` 与 `Saved/Logs/M11F_HUD_M11D.log`。正式可见 PIE 仍需人工检查鼠标点击、拖动、滚轮、精度档切换，以及 F4 目标缺口随三个目标值变化时的连续性和辨识度。

回退时只需恢复 `DrawKnob` 的旧绘制实现与调用签名；交互数据、命中盒、按钮资产和共享 Theme 均无需回退。
