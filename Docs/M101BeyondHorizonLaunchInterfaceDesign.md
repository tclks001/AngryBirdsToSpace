# M10.1：道路外目标标记与引力走廊发射界面设计

> 状态：玩法与界面方案完成，尚未进入 C++ 实现。
>
> 文档定位：本稿只定义“已侦察道路外目标”的超视距选择、引力走廊计算、发射相机与 HUD 表现。它不改变 M10 的侦察来源，不替代 M6 的实际弹道和碰撞，不公开未侦察区域，也不把发射改成自动寻的。
>
> 导航：[主设计稿](AngryBirdsToSpaceGameDesign.md) · [M6 弹弓发射与碰撞](M6SlingshotLaunchAndImpactDesign.md) · [M9 卫星与局部引力](M9SatelliteGravityDesign.md) · [M10 青翎侦察小地图](M10ScoutMinimapDesign.md) · [UI 系统设计](UISystemDesign.md)

## 1. 要解决的问题

球面地图同时带来三件事：建筑会被地平线遮挡；玩家站在弹弓处无法凭肉眼判断背面目标方位；即使已通过青翎侦察知道目标存在，也很难把局部的鼠标拉弓动作与数秒后的远端掠过联系起来。

M10.1 的目标不是消除这个空间推理，而是把它拆成可学习的三步：

1. **先侦察**：未知目标仍然未知，青翎行动是情报门槛；
2. **再捕获走廊**：玩家找到一组“可能经过目标附近”的角度和拉力范围；
3. **最后精调**：玩家用当前虚线轨迹、最近掠过量和远端接近窗把一次具体发射调进走廊。

最终体验应满足：玩家知道“目标大致在球面哪一侧、当前弹弓能否够到、应该往哪个方向调”，但系统不提供唯一答案，不自动转动弹弓，也不保证一次命中弱点。

## 2. 调研结论

### 2.1 可借鉴的做法

| 游戏或研究 | 可观察的设计 | 对本项目的启示 |
| --- | --- | --- |
| 《Angry Birds Space》及 Rovio 后续 Space 玩法 | 用清晰的引力区域和实时预测轨迹，把原本不可直觉估算的曲线运动变成可试验的物理谜题 | 引力必须可见，当前这一发的轨迹必须比目标提示更醒目；不能只给一个屏幕外箭头 |
| 《Kerbal Space Program》机动节点 | 玩家先修改少量发射参数，再从预测轨道和交会结果理解这些参数的后果 | 走廊应表达“可行参数范围”，当前轨迹表达“本次具体结果”；两者不能混成自动瞄准线 |
| 《Outer Wilds》信号镜 | 先获得方向性信号，再靠转向、频段和接近完成识别；官方介绍明确把 Signal Scope 用于追踪神秘音频 | 未侦察目标不显示；已获得情报后先给方向，再逐步给精确反馈，比全图永久透视更有探索感 |
| 《塞尔达传说：旷野之息》望远镜/希卡之石 | 从高处观察，使用 Scope 识别远方兴趣点，再把发现转成地图上的长期信息 | “发现”应成为持久情报；M10 小地图是情报来源，发射 HUD 只是消费情报，不能反向替玩家侦察 |
| Wedge 等屏幕外目标可视化研究 | 屏幕边缘的楔形/弧形提示能同时表达方向与屏幕外距离，并减少多个普通箭头挤在同一点的问题 | 背面目标使用沿屏幕安全框展开的方向弧，不在球体表面画穿透图标；目标多时按角度分布并聚合 |

### 2.2 不采用的方案

- **全星球自由战略相机**：会立即暴露背面轮廓，削弱青翎侦察，也会让一次发射在局部操作和全局地图间频繁切镜。
- **隔墙显示建筑模型轮廓**：目标位置和体量一览无余，隐藏建筑不再“隐藏”；建筑坍塌后轮廓更新成本也高。
- **选择目标后自动吸附角度/拉力**：把引力谜题降为点选按钮，卫星和弹弓参数失去玩法意义。
- **每帧对所有目标穷举全部弹道**：目标越多越卡，而且当前 M6 每帧已有一条轨迹积分；走廊应按事件缓存。

## 3. 推荐方案：双尺度、三层辅助

M10.1 采用一套界面、两个空间尺度、三层瞄准反馈：

- **本地尺度**：保留 M6 固定在弹弓弦后方的相机。玩家仍能看清桩、弦、弹珠袋、鼠标拉伸方向和近端虚线。
- **球面尺度**：屏幕边缘方向弧表示目标在球面上的大圆初始方向；右上“目标接近窗”只显示目标附近的小范围俯视示意，不显示完整星球。
- **三层反馈**：方向弧负责“往哪里找”，引力走廊负责“哪些角度/拉力可行”，当前预测轨迹负责“这一发会怎样”。

```text
┌──────────────────────────────────────────────────────────────────┐
│  M10 侦察小地图                         [目标接近窗]             │
│  （历史情报，不旋转）                    建筑图标      ○预计掠过点 │
│                                      目标捕获圈  ← 终端轨迹箭头 │
│                                                                  │
│  ‹ 已侦察目标 2/3   石塔仓库   中程 ›                             │
│  ╭──────── 屏幕边缘目标方向弧 / 地平线门 ────────╮               │
│  │                      ·  ·  · 当前轨迹          │               │
│  │               ╱ 半透明青色引力走廊             │               │
│  │          弹弓 / 鸟 / 弹珠袋                    │               │
│  ╰──────────────────────────────────────────────╯               │
│                  最近掠过  286 cm   [偏高]                       │
│           方向  ◀■■□▶       拉力  ◀■■■□▶                         │
└──────────────────────────────────────────────────────────────────┘
```

图中目标接近窗是二维战术示意，不是第二台 SceneCapture 相机。它使用目标局部切平面、建筑图标、捕获圈和预测轨迹末段绘制，因此不会透视展示未侦察景物，也没有第二次渲染场景的性能成本。

## 4. 信息揭示规则

### 4.1 四级目标情报

| 情报状态 | 世界/发射 HUD 表现 | 获得方式 |
| --- | --- | --- |
| `Unknown` 未知 | 完全不显示，不参与目标切换和走廊计算 | 尚未进入任何有效青翎侦察圆 |
| `Scouted` 已侦察 | M10 地图显示建筑；进入发射模式后显示低精度方向弧和近/中/远档位 | 建筑处于 M10 当前侦察圆内且仍有存活模块 |
| `Reachable` 可达 | 方向弧变亮；显示至少一条引力走廊和推荐调整方向 | 当前鸟、弹弓档位和允许拉力域存在可行轨迹族 |
| `CorridorLocked` 走廊捕获 | 显示目标接近窗、预计最近掠过距离和进入方向；提示音只播放一次 | 当前预测轨迹进入某条走廊容差 |

M10 当前设计是“新一次侦察替换旧地图”，因此 M10.1 首版也只消费**当前有效侦察圆**，不暗中积累全星球目标。以后若 M10 引入战争迷雾并集，M10.1 可以自然消费持久目标记录，但无需更改本规则。

### 4.2 道路外目标资格

目标同时满足以下条件才进入 M10.1 候选：

1. 来自 TaskGraph 建筑，具有有效逻辑锚点 Cell；
2. `RoadDistanceCells >= BeyondRoadTargetMinDistanceCells`；
3. 该建筑位于当前 M10 侦察圆内；
4. 至少有一个存活建筑模块；
5. 当前弹弓处于正式球面地图，不是 M7.1 平面测试台。

道路距离、任务材料和任务身份来自 CellTopo/TaskGraph；连续球面仅提供建筑实时质心与界面投影。被 Chaos 推动后的建筑可用存活模块质心更新显示位置，但不能因此改变它原本是不是“道路外任务目标”。

### 4.3 背面目标不画穿透图标

计算弹弓径向单位向量 `S`、目标径向单位向量 `T`：

```text
AngularDistance = acos(clamp(dot(S, T), -1, 1))
InitialTangent  = normalize(T - S * dot(S, T))
```

- 目标位于当前视锥且未被主星遮挡时，使用普通目标框；
- 目标离屏但仍在近半球时，方向弧贴屏幕安全框；
- 目标在球面背面时，方向弧附着到 `InitialTangent` 指向的地平线门，并增加一圈虚线，表示“沿此大圆方向越过地平线”，绝不把图标画在建筑的透视屏幕坐标上；
- 多目标方向相差小于 `TargetArcMergeDegrees` 时聚合为 `×N`，切换目标后才展开当前项。

这样玩家能知道该往球面的哪一侧发射，但不能从一枚隔墙图标直接反推建筑外形或弱点。

## 5. 玩家操作闭环

### 5.1 进入与选择

1. 点击可用弹珠袋，进入现有 M6 `Ready`；
2. 系统读取当前 M10 情报，筛选道路外目标；
3. `Q / E` 循环上一个/下一个已侦察目标，`R` 清除锁定并回到纯自由发射；
4. 目标切换只允许在 `Ready`，开始按住弹珠袋进入 `Pulling` 后锁定，避免拖拽过程中 UI 跳变；
5. 无目标或玩家清除目标时，M6 完全保持原有自由发射体验。

不把左键目标选择绑定到世界建筑：左键已经负责命中弹珠袋、拉伸和释放。若 HUD 后续改为可交互控件，可允许点击目标卡切换，但必须由 UI 消费事件，不能把点击穿透给弹珠袋。

### 5.2 粗调：捕获引力走廊

- 选择目标后显示屏幕边缘方向弧；
- 若存在可达轨迹族，弹弓前方显示一条短的半透明走廊入口，HUD 底部显示“方向”和“拉力”两条偏差尺；
- 偏差尺只给 `偏左/偏右`、`偏高/偏低`、`力度不足/过强`，不显示唯一角度和唯一 PullAlpha；
- 当前参数进入走廊容差时，入口由灰蓝变为青色，播放一次轻提示音，状态进入 `CorridorLocked`。

### 5.3 精调：当前轨迹与目标接近窗

- M6 现有浅色虚线继续表示当前这一发，是屏幕中最亮的轨迹；
- 近端轨迹在世界中绘制；越过可见地平线后的部分不穿过星球显示，而被裁切并转译到右上目标接近窗；
- 接近窗显示目标捕获圈、轨迹进入方向、预计最近掠过点和数值；
- 颜色分三级：`Miss` 红灰、`Near` 琥珀、`Intercept` 青绿；
- `Intercept` 只表示轨迹会经过建筑的**外围捕获半径**，不保证击中实体，更不保证击中弱点。

### 5.4 发射与飞行

- 松开左键后所有走廊、参数尺和接近窗淡出；
- 保留一枚低干扰的目标方向标，发射相机按 M6 跟随鸟；
- 实际飞行继续由 M6/M9 物理决定，不读取走廊结果，不施加吸附力和中途修正；
- 目标在发射后移动或坍塌时，方向标跟随存活模块质心，但已发射弹道不重新规划。

## 6. 引力走廊定义

### 6.1 它是什么

“引力走廊”不是场景中真实存在的轨道或空气管道，而是当前发射条件下的一组可行初速度：

```text
LaunchParameter p = (AimPlaneOffsetX, AimPlaneOffsetY, PullAlpha)
Trajectory Xp(t)  = Integrate(p, PrimaryGravity + SatelliteGravity + AirDrag)
Closest(p, Target)= min_t distance(Xp(t), TargetCaptureVolume)
Feasible(p)       = Closest <= CaptureRadius
                    && no planet-surface penetration
                    && flight time <= MaxPredictionSeconds
```

所有相邻的 `Feasible(p)` 样本在参数空间形成一个或多个连通簇；每个簇就是一条候选走廊。世界中的带状表现只是把该簇的若干代表轨迹画成半透明包络，真正用于辅助的是“当前参数到最近可行簇的距离”。

### 6.2 主星走廊与卫星走廊

- **主星引力走廊**：轨迹主要受主星径向引力弯折，使用青色；
- **卫星助推走廊**：若轨迹进入卫星影响阈值，且卫星累计速度改变量超过 `SatelliteAssistMinDeltaVCMPerSec`，使用紫青渐变，并在接近窗标出卫星掠过门；
- 同一目标存在多簇时，默认选择容差最宽、地表净空最大、飞行时间较短的一簇；玩家可用 `Q/E` 的二级操作切换走廊，但比赛首版最多显示每目标 2 条，避免界面过载。

这使卫星成为能够拓展可达域的 Gameplay 设施，而不只是让单条虚线轻微偏折。

### 6.3 表面和目标判定

走廊预测不检查树、石头或建筑碰撞，保持与 M6 当前“预览不计算碰撞反弹”的约定；但必须做低成本主星表面净空检查，避免一条穿过星球内部的轨迹被判为可达。表面高度查询应复用 M3 的 CPU 连续地表接口，不能只用基础半径。

目标捕获体首版使用存活模块包围盒外扩后的球体：

```text
CaptureRadius = clamp(BuildingBoundsSphereRadius * CaptureRadiusScale,
                      MinTargetCaptureRadiusCM,
                      MaxTargetCaptureRadiusCM)
```

UI 只显示这个外围捕获圈；真正击中仍由 Chaos 碰撞决定。

## 7. 走廊生成与缓存

### 7.1 自适应采样

推荐两阶段采样，而不是建立高分辨率三维体素：

1. **粗采样**：在合法 `AimPlaneOffsetX/Y` 与 `PullAlpha` 内取 `7 × 7 × 5 = 245` 个样本，每条最多积分 80 步；
2. **局部细化**：只在 `Closest` 较小的前 8 个样本附近细分两轮，每轮每中心 12 个邻域样本；
3. 对可行样本按参数距离并查成连通簇，计算每簇中心、范围、净空和鲁棒分数；
4. 缓存到“弹弓实例 + 鸟种 + 目标稳定 ID + 物理配置版本”的键下。

目标切换、弹弓档位变化、鸟种变化、主星/卫星引力参数变化或目标质心移动超过阈值时才失效。鼠标每帧拖动只查询最近走廊并积分**当前一条**轨迹，不重新穷举。

### 7.2 允许近似，但必须同源

M6 当前 `DrawPredictedTrajectory()` 在私有函数中直接积分主星引力、`ABTSM9Gravity::GetSatelliteAcceleration` 和空气阻力。M10.1 落地前应先把这段抽成无渲染的共享预测器，使以下三者消费同一函数：

- 当前 M6 虚线；
- M10.1 走廊批量采样；
- 目标接近窗的最近掠过计算。

不能在 HUD 里再写一份公式，否则卫星参数或阻力修改后会出现“走廊说能到，实际虚线到不了”。运行时真实 Chaos 仍是最终权威；预测器只保证初始条件和逐步力模型同源。

## 8. 相机方案

### 8.1 Ready / Pulling

保留 `AABTSM6SlingshotCamera` 当前规则：相机基于进入发射模式时捕获的 `SlingCenter / SlingForward / SlingUp`，保持 Roll 锁定，拖动弹珠袋不转动相机。M10.1 不为了背面目标把镜头绕到星球外，也不让相机朝边缘图标持续旋转。

只增加两种轻量构图变化：

- 选中目标时，FOV 在 `TargetAimFOVDegrees` 内缓慢变窄，突出弹道，不改变相机轴；
- `CorridorLocked` 时，相机沿现有后方轴后退 `CorridorLockedCameraPullbackCM`，让近端走廊更完整地进入画面。

两者必须平滑插值，并在清除目标时回到 M6 默认值。对当前 M6 已验收构图影响很小。

### 8.2 为什么用接近窗而不是切镜

背面目标与弹弓无法同时在一个透视镜头中出现。强行把两者框进画面只能把镜头拉得极远，弹珠袋和鼠标关系会变得不可读；切到远端镜头又会让玩家看不见正在拖拽的弹弓。二维接近窗保留两端的信息，但只揭示已侦察目标和预测终端段，是本阶段成本和玩法最平衡的方案。

### 8.3 可选的后续总览

若实机仍难理解曲线，可在 `Ready` 增加“按住 Alt 查看轨道总览”：相机只拉高到能看到发射点附近不超过半颗星球，松开立即回到本地瞄准。总览中仍不画背面建筑轮廓。该功能不纳入 M10.1 首版验收，避免相机状态进一步复杂化。

## 9. HUD 视觉规范

### 9.1 层级

从强到弱依次为：当前预测轨迹 > 当前目标与接近结果 > 引力走廊 > 其他目标方向弧 > M10 小地图。未选中目标必须降低透明度，走廊不能盖住弹珠袋或鸟体。

### 9.2 颜色与形状

| 元素 | 建议表现 |
| --- | --- |
| 当前轨迹 | 浅蓝实心点/短划，保持现有 M6 识别度 |
| 主星走廊 | 低透明青色带，边界柔和，中间不画实线 |
| 卫星走廊 | 紫到青渐变带，卫星掠过门为双圆环 |
| 已侦察但不可达 | 灰蓝方向弧、断开的走廊入口、`当前弹弓不可达` |
| 接近但未截获 | 琥珀捕获圈和最近掠过点 |
| 已截获 | 青绿捕获圈短促脉冲，不持续闪烁 |
| 背面目标 | 目标图标外加虚线环；不画 X-Ray 轮廓 |

所有状态除颜色外还要有形状差异，避免只靠红绿判断。

### 9.3 文字最小化

默认只显示目标名/材料类型、近中远、最近掠过距离和不可达原因。不要显示经纬度、精确初速度、最佳角度或完整求解公式。比赛演示可用 Debug 层显示样本数、缓存命中、走廊 ID、飞行时间和净空，但 Shipping 默认关闭。

## 10. 建议的编辑器参数

未来建议放在 `AABTSM10GameMode` 的 `ABTS | M10.1 | Beyond Horizon Aim`，计算参数由专门配置结构持有，HUD 不直接拥有物理阈值。

| 参数 | 建议默认值 | 作用 |
| --- | ---: | --- |
| `EnableBeyondHorizonAim` | `true` | 总开关；关闭后完全退回 M6 |
| `BeyondRoadTargetMinDistanceCells` | `3` | 道路外候选最小图距离 |
| `MaximumSelectableTargets` | `6` | 单次侦察可进入发射切换的目标上限 |
| `TargetArcMergeDegrees` | `8°` | 屏幕边缘方向弧聚合角度 |
| `CoarseAimSamplesPerAxis` | `7` | X/Y 粗采样数 |
| `CoarsePowerSamples` | `5` | PullAlpha 粗采样数 |
| `CorridorRefinementRounds` | `2` | 局部细化轮数 |
| `CorridorMaxPredictionSeconds` | `7.5 s` | 超视距预测上限；高于当前 M6 约 4.05 s |
| `CorridorPredictionStepSeconds` | `0.075 s` | 首版与 M6 当前积分步长一致 |
| `MinTargetCaptureRadiusCM` | `220 cm` | 小建筑最低外围捕获半径 |
| `MaxTargetCaptureRadiusCM` | `900 cm` | 防止大建筑走廊过宽 |
| `CaptureRadiusScale` | `1.15` | 建筑包围球到捕获体的倍率 |
| `NearMissExtraRadiusCM` | `350 cm` | 琥珀 Near 区宽度 |
| `MinimumSurfaceClearanceCM` | `80 cm` | 走廊轨迹对连续地表的最小净空 |
| `SatelliteAssistMinDeltaVCMPerSec` | `80 cm/s` | 判为卫星助推走廊的累计影响阈值 |
| `TargetAimFOVDegrees` | `46°` | 选中目标后的 FOV；M6 当前默认 50° |
| `CorridorLockedCameraPullbackCM` | `160 cm` | 捕获走廊后的轻微后退量 |
| `TargetInsetDiameterPx` | `230 px` | 右上接近窗直径 |
| `ShowBeyondHorizonDebug` | `false` | 样本、簇、缓存与拒绝原因 Debug |

`CorridorMaxPredictionSeconds` 必须足以覆盖一次绕行，但不应允许多圈轨道。首版一旦轨迹超过目标或完成约一圈主星角距离就终止，防止出现玩家难以理解的多圈解。

## 11. 与现有系统的接口关系

### 11.1 M10 情报接口缺口

当前 `AABTSM10ScoutMapSystem` 只公开已投影的 `FABTSM10ScoutMapMarker`；建筑 Marker 只有类型和二维地图位置，没有稳定 ID、真实世界位置、Task、RoadDistance 或存活包围体。M10.1 不能反向从二维图标猜世界目标。

实现时应新增只读目标快照，例如：

```text
FABTSM101ScoutedTarget
  StableTargetId
  TaskId / AnchorCellId / RoadDistanceCells
  LiveWorldCentroid / LiveBoundsRadiusCM
  RequiredMaterialType / BuildingIcon
  IntelligenceState
```

由 M10 世界系统从其已侦察建筑集合生成，HUD 和走廊系统只消费快照；不得长期缓存 Actor 裸指针或 HISM InstanceIndex。

### 11.2 M6 预测接口缺口

当前 `DrawPredictedTrajectory()` 只画 DebugPoint，不返回采样点、最近掠过或终止原因。实现 M10.1 前应抽出共享 `PredictTrajectory(InitialState, Config, OutSamples, OutSummary)`。M6 保留绘制职责，M10.1 只读取结果。

### 11.3 M9 引力接口

卫星引力已通过 `ABTSM9Gravity::GetSatelliteAcceleration(World, Position)` 同时接入真实飞行和 M6 预览。走廊必须继续调用该查询，不能保存卫星默认参数的副本。

### 11.4 CellTopo 与连续球面

- CellTopo/TaskGraph：目标身份、道路距离、任务材料、是否被侦察；
- 连续球面：相机遮挡、目标实时质心、建筑 Bounds、轨迹表面净空与表现；
- Chaos：实际命中、位移、破坏和材料回收。

该分层继续满足“CellTopo 永远是球面 Gameplay 逻辑源；连续球面只负责碰撞和表现”的项目约束。

## 12. 性能预算

- 进入发射模式时只为当前目标计算走廊；其他目标先显示方向和“待分析”，切换后再计算。
- 单次粗采样默认约 `245 × 80 = 19,600` 个积分步，细化后总预算控制在 35,000 步以内；应分 2–4 帧完成，期间方向弧可立即显示，走廊显示短暂扫描动画。
- 当前鼠标轨迹每帧最多 100 步；HUD 最近掠过从同一采样结果读取，不重复积分。
- 每个发射会话最多缓存 6 个目标、每目标 2 个走廊；退出发射模式释放世界轨迹点，只保留轻量参数簇。
- 目标接近窗使用 Canvas/Slate 图元或一次 Dynamic Mesh 绘制，不使用 SceneCapture2D、RenderTarget 或第二套地形采样。
- 建筑存活质心沿用 M10 的低频环境刷新；Pulling 中若目标变化超过 `TargetCacheInvalidationDistanceCM`，只标记预测过期，不在同一帧重算。

## 13. 风险与处理

| 风险/症状 | 原因 | 处理 |
| --- | --- | --- |
| 一选择目标就看见星球背面全部建筑 | 发射 HUD 绕过 M10 直接枚举世界 Actor | 候选只能来自当前侦察目标快照 |
| 边缘多个箭头挤成一团 | 普通 Clamp-to-screen 没有聚合 | 使用方向弧与角度聚合，当前目标单独展开 |
| 走廊和实际虚线不一致 | 两套积分公式或步长不同 | 抽取共享预测器，并用物理配置版本使缓存失效 |
| 走廊穿过山体仍显示可达 | 只检查基础球半径 | 每个积分段查询 M3 连续表面净空 |
| 玩家只需把指针塞进绿色带就必中弱点 | 捕获体过小且 UI 直接代表实体命中 | 捕获圈只代表建筑外围；不预测砖块/弱点碰撞 |
| 卫星走廊满屏都是紫色 | 只以“受到过卫星力”分类 | 使用累计 DeltaV 和影响距离双阈值 |
| 选目标时明显卡顿 | 同帧计算所有目标全部走廊 | 当前目标按事件分帧计算，其余延迟 |
| 接近窗泄露未侦察资源和地形 | 复用了完整小地图或 SceneCapture | 只画已知目标图标、捕获圈和终端轨迹 |
| 拉弓时目标突然切换 | Q/E 或 UI 点击未按状态过滤 | 只在 Ready 接受目标切换，Pulling 锁定 |
| 背面目标看似就在屏幕边缘 | 边缘箭头没有远近语义 | 虚线环 + 近/中/远档位；不伪装成普通可见目标框 |

## 14. 验收清单

### 14.1 情报公平性

- [ ] 未经青翎侦察的道路外建筑不会出现在发射 HUD、目标列表或走廊计算中。
- [ ] M10 当前侦察圆内的存活道路外建筑可以被 Q/E 选择；被完全摧毁后消失。
- [ ] 背面目标只显示地平线方向弧和虚线环，不显示隔墙建筑轮廓。
- [ ] 目标很多时方向弧会聚合，当前目标始终可辨认。

### 14.2 瞄准与相机

- [ ] 进入目标瞄准后仍能清晰看到弹弓桩、双弦、弹珠袋和当前鸟。
- [ ] 拖动弹珠袋不会旋转发射相机，镜头无 Roll、无突变。
- [ ] 当前轨迹越过地平线后不会穿星球绘制，而在目标接近窗显示终端段。
- [ ] 参数进入可达簇后显示 CorridorLocked，但松手后的鸟不受任何自动吸附力。
- [ ] 清除目标后恢复原 M6 自由发射，所有辅助界面退出。

### 14.3 引力与结果一致性

- [ ] 主星走廊、卫星助推走廊有明确视觉区别。
- [ ] 修改 M9 卫星引力后，走廊与当前虚线同时变化，旧缓存不会继续显示。
- [ ] 走廊不会接受穿过连续地表的轨迹。
- [ ] `Intercept` 代表进入建筑外围捕获体；是否真正命中和破坏仍由 Chaos 决定。
- [ ] 相同输入下，接近窗的预计掠过趋势与实际飞行方向一致。

### 14.4 性能

- [ ] 选择目标后方向弧立即出现，走廊可分帧完成，游戏不会出现长帧冻结。
- [ ] Pulling 中每帧只更新当前轨迹和最近走廊查询，不重算全部样本。
- [ ] 默认 6 个候选目标不会创建 SceneCapture、额外球面网格或全星球 Actor 扫描。

## 15. 首版实现边界与建议顺序

首版只做一颗主星、一颗 M9 卫星、当前 M10 侦察圆、最多 6 个建筑目标和每目标最多 2 条走廊。不做多圈轨道、运动目标提前量、弱点级自动识别、跨卫星表面着陆、多人同步或全局战争迷雾持久化。

建议实施顺序：

1. 扩展 M10 只读建筑目标快照，先验收“未知不出现”；
2. 从 M6 抽出共享弹道预测器，保证当前虚线完全不变；
3. 实现目标方向弧和 Q/E 选择，不做走廊；
4. 实现单目标离线走廊采样、缓存与不可达原因；
5. 实现目标接近窗和越地平线轨迹裁切；
6. 最后增加卫星走廊分类、声音与相机轻微构图变化。

这个顺序保证任一步失败都能退回前一层工作玩法，不需要一次性改写 M6 发射状态机。
